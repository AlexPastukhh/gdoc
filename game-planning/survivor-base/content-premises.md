## 1. Responsibility And Authority

Reusable `Content Premise` meaning is owned by [`Game Planning — Principles And Terminology`](../../principles/game-planning-principles-and-terminology.md). This project file applies that meaning to Survivor Base.

A premise here is a sufficiently concrete playable/content unit that can be imagined and preliminarily evaluated as its own piece of game content, but is not yet a detailed Scenario.

A premise may be:

```text
a crisis;
an encounter;
a special base/world state;
a start configuration;
an event;
another concrete playable content unit.
```

It does **not** yet require:

```text
exact Scenario Beats;
exact Situation Instances;
exact timings;
the only route through the content;
all underlying mechanics to be resolved.
```

Everything in this file is preliminary/candidate content meaning unless explicitly stated otherwise.

```text
Content Premise
≠ accepted cross-cutting game rule
≠ detailed Scenario.
```

If developing a premise requires new general mechanics/system meaning, discuss and accept that meaning in the appropriate owner and reconcile accepted cross-cutting changes into the Game Planning Draft.

If a premise becomes sufficiently defined to need chronology/integration work, expand it through the reusable Scenario method and place the detailed representative Scenario in [`scenarios.md`](scenarios.md) or another justified project Scenario owner.

Hybrid incoming ideas remain in [`ideas.md`](ideas.md) by default until their content fragment is useful as an independent unit.

## 2. Current Premises

### CP-001 — Prolonged Horde / “Nuclear Winter” Siege

**Source:** `SB-B01-SRC01 item 1`; preserved as standalone content meaning during the baseline review.

**Original wording — verbatim:**

> Период типа ядерной зимы когда не можешь выйти наружу. Но только из за огромной орды, которая облепляет базу со всех сторон, жрет себя, орет когда видит и не видит персонажей, делает лесенки так что верхние этажи могут быть не защищены, плетутся, воняет и разносит заразу сильнее т к воздух пропитан ею. На крышу может залезть, а на крыше может не быть ограды и могут быть важные строения и тогда придется круглые сутки мониторить крышу и копьями сбивать тех кто лезет. Толпа и на нервы влияет.

**Premise:**

A prolonged period where an enormous infected mass effectively cuts the base off from the outside world and sustained pressure reaches not only the ground perimeter but upper levels / roof access, forcing the base to survive from internal reserves while monitoring, repairing and defending vulnerable exterior surfaces.

**Why this is a separate content unit:**

Existing horde/perimeter systems can support parts of it, but the premise is specifically about a **long-duration operating state** rather than one short attack.

Potential value includes:

- external operations become severely constrained;
- roof infrastructure can become operationally dangerous or inaccessible;
- continuous monitoring/defense competes with normal labor;
- repair/sanitation/resource pressure accumulates;
- constant crowd noise/presence can create persistent psychological pressure.

**Unresolved attached system questions:**

- exact conditions and duration for entering/leaving this state;
- how upper-floor/roof climbing works;
- whether body piling/ladders are systemic enough for this premise;
- what roof facilities matter;
- how much active defense is required;
- whether smell/biological contamination has gameplay meaning;
- the original idea of stronger air infection under huge density is **not accepted automatically** because the current project does not yet own a full Air network.

**Possible Scenario handoff:**

A future Scenario can test:

```text
normal operating base
→ horde closes external routes
→ pressure migrates to roof/upper access
→ labor/resources are reallocated
→ one or more internal/external systems fail
→ player chooses what to preserve
→ siege ends / base adapts / territory is lost.
```

Do not freeze this chronology yet.

### CP-008 — Most Of The Facility Lost

**Source:** `SB-B01-SRC01 item 8`.

**Original wording — verbatim:**

> Ситуация - потерял большую часть здания, сидишь на обрызге.

The phrase `сидишь на обрызге` is unclear in the incoming source and is intentionally **not interpreted or corrected** here.

**Premise:**

Most of the facility has been lost and the player continues from a much smaller remaining viable position.

**Potential content value:**

This tests a recovery game state rather than only the immediate containment event:

```text
large territorial/infrastructure loss
→ preserve a minimal viable base
→ decide what is essential
→ adapt logistics and population placement
→ decide whether/what to reclaim
→ accept some permanent losses.
```

**Existing-system basis:**

The current project already has enough basis for lost/blocked/dirty sectors, people/equipment left behind, alternative routes, later reclamation and permanent scars. Those mechanics do not make this premise redundant.

**Open questions:**

- how small the remaining viable area can become;
- what makes the state survivable instead of an automatic loss;
- which capabilities/resources are normally stranded;
- whether recovery or abandonment is the main tension;
- how long the reduced-base state should last;
- what new Situations and Loops appear when normal space/capacity assumptions collapse.

### CP-009 — First Floor Lost — Descend From Above

**Source:** `SB-B01-SRC01 item 9`.

**Original wording — verbatim:**

> Ситуация - потерял первый этаж, надо спускаться со второго, с возможностью того что выбегать будут на тебя, т к там же свежие зараженные. Они в целом и на второй могут попытаться залезть.

**Premise:**

The first floor has been lost. The controlled/safe position is above it, so the player must descend into the dangerous lower floor while fresh infected can rush upward and potentially threaten the second floor.

**Why it is distinct:**

It creates a useful spatial inversion:

```text
normal:
  danger approaches from outside
  → player holds the perimeter;

this premise:
  safe position is above
  → dangerous space lies between the player
    and the normal outside world / lower access.
```

**Possible decision areas for later Scenario work:**

- descend now or delay;
- choose a route;
- scout vs force entry;
- choose who goes;
- create/seek another exit;
- risk people to recover infrastructure;
- decide whether the first floor is even necessary immediately;
- manage fresh infected attempting to climb upward.

These are candidate questions, not a frozen Situation list.

## 4. Preliminary Review Questions

Use only the questions that help:

```text
What is the concrete playable/content premise?
Why is it distinct from existing premises?
Which current systems already support it?
Which unresolved rules does it depend on?
What meaningful decisions could plausibly appear?
What Experience does it promise?
Does it expose a useful extreme/system interaction?
How expensive is the authored content burden?
Does it deserve detailed Scenario work now?
```

A premise does not need to answer all of these before it can be preserved.

## 5. Lifecycle

```text
incoming / embedded idea
→ Content Premise when it becomes an independent content unit
→ preliminary review
→ keep / refine / defer / reject

if new cross-cutting game meaning is required:
  discuss → decide → reconcile into Game Planning Draft

if chronology/integration detail is useful:
  expand through Scenario planning
  → project Scenario owner/view.
```
